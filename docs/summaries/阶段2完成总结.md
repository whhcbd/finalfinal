### 2. 数据流架构

完整的数据流现在是：

```
1. 用户发送消息
   ↓
2. 后端生成 A2UI 消息序列：
   - beginRendering (root: "main_component")
   - surfaceUpdate (组件使用 path 绑定)
   - dataModelUpdate (设置初始数据)
   ↓
3. 前端通过 WebSocket 接收消息
   ↓
4. A2UIRenderer 处理所有消息：
   - 创建 surface
   - 渲染组件（使用 path 绑定）
   - 更新数据模型
   ↓
5. 组件自动响应数据变化（响应式更新）
   ↓
6. 后续的 dataModelUpdate 消息可以实时更新组件
```

### 3. 数据绑定示例

**之前（静态值）：**
```json
{
  "PunnettSquare": {
    "parent1Genotype": {"literalString": "Aa"},
    "parent2Genotype": {"literalString": "aa"}
  }
}
```

**现在（数据绑定）：**
```json
{
  "PunnettSquare": {
    "parent1Genotype": {"path": "/parent1"},
    "parent2Genotype": {"path": "/parent2"}
  }
}
```

**dataModelUpdate 消息：**
```json
{
  "dataModelUpdate": {
    "surfaceId": "genetics_ui",
    "contents": [
      {
        "path": "/parent1",
        "value": {"valueString": "Aa"}
      },
      {
        "path": "/parent2",
        "value": {"valueString": "aa"}
      }
    ]
  }
}
```

## 📝 技术要点

### 关键实现细节：

1. **A2UIRenderer.updateDataModel()**
   - 接收 surfaceId 和 dataModelUpdate 消息
   - 使用已保存的 processor 处理更新
   - 触发组件的响应式更新

2. **ChatOrchestrator.handleDataModelUpdate()**
   - 从消息中提取 surfaceId
   - 调用 renderer 的 updateDataModel 方法
   - 添加错误处理和日志

3. **持久化消息处理器**
   - 在 WebSocket 连接时注册 dataModelUpdate 处理器
   - 确保实时消息能够被正确路由和处理

4. **Processor 管理**
   - 每个 surface 的 processor 被保存在 Map 中
   - 支持后续的增量更新操作
   - 避免重复创建 processor
